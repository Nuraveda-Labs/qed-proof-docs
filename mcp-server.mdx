title: MCP server
description: Connect QED Proof to an MCP client over local stdio or hosted Streamable HTTP.
---

The `@qed-proof/mcp` package exposes QED Proof as tools to an MCP client. It requires Node.js 20 or later. The server
offers `submit_claim`, `get_verdict`, `get_receipt`, `verify_receipt`, `list_claims`, and `list_connections`.

## Create a key

Create a workspace API key in the [QED Proof app](https://qedproof.site/app), under **Developers → API keys**. A claim's
`target` and `params` are included in its receipt, which is public and permanent. Do not submit secrets or private
content in these fields.

## Local server with Claude Code

The local server uses stdio and reads the key from `QED_API_KEY`. Run this command, replacing the placeholder with your
workspace key:

```bash
claude mcp add qed-proof --env "QED_API_KEY=<your key>" -- npx -y @qed-proof/mcp
```

`QED_AGENT_ID` optionally sets the default agent ID for claims. `QED_API_URL` changes the API endpoint when using a
self-hosted node; it defaults to `https://api.qedproof.site`. Offline receipt verification works without a key; the
other tools need one.

## Hosted server with Claude Code

The hosted Streamable HTTP endpoint is `https://mcp.qedproof.site/mcp`. Add it with bearer authentication:

```bash
claude mcp add --transport http qed-proof https://mcp.qedproof.site/mcp \
  --header "Authorization: Bearer <your key>"
```

The hosted server forwards the key to the API for each request. It keeps no application state; its logs include the
method, tool name, status, and latency.

## Other apps

Any app that can add a remote MCP server by URL with a bearer header, or run a local stdio server, works the same way.
The **Connect apps** page in the [QED Proof app](https://qedproof.site/app/connect/) has the exact steps for Claude Code,
Claude Desktop, Cursor, VS Code, Windsurf, Gemini CLI, Codex CLI, Cline and Zed, with a key made for each app so you can
revoke one without breaking the others.

Two apps can't connect yet. **claude.ai** (web and mobile) and **ChatGPT** connect to a remote server with an OAuth
sign-in, and QED Proof doesn't have one yet. ChatGPT has no field for an API key at all. claude.ai accepts a key only in
organizations that are in Anthropic's request-headers beta. Until OAuth sign-in is added, use Claude Code, Claude Desktop
or one of the editors above.

## What the tools do

`submit_claim` asks QED Proof to check a destination. `get_verdict` reads the claim's state and outcome;
`get_receipt` returns the public receipt. `verify_receipt` checks a receipt offline, including its signature and log
inclusion. It also checks change entries (a change nobody claimed, recorded in the log), and with an optional `pipeline`
document it checks the entry's `policy`. It does not check an on-chain anchor, so that check remains unproven. The list tools return the claims and
connected destinations available to the workspace.

Only actions with a published verifier profile can receive a verified outcome. Other actions can be submitted, but
will be decided as `unverifiable`. See [verdicts](/concepts/verdicts) and [connectors](/connectors/overview) for
current verification coverage.

See the [Python SDK](/sdks/python), [TypeScript SDK](/sdks/typescript), or [CLI](/cli), or read the
[`@qed-proof/mcp` package instructions](https://www.npmjs.com/package/@qed-proof/mcp).
